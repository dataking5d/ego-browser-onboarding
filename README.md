# ego-browser-onboarding

面向零基础用户的**浏览器实操引导 Skill**。它不是可执行程序，而是一份 `SKILL.md` 指令文档：agent 加载后按固定节奏分五个阶段推进，带用户完成从安装浏览器到交还主动权的全过程。

原始文件名：`引导实操各网站自动化.md`。本仓库中的 `SKILL.md` 与原文逐字节一致，未做删改。

## 它解决什么问题

零基础用户想让 AI 帮忙操作某个网站时，通常卡在三个地方：不知道该装什么、不知道怎么授权、说不清自己要什么。本 Skill 把这三件事拆成可逐步确认的阶段，并在最后一阶段用开放式提问引导用户把需求说具体，从而把同一套方法迁移到任意站点。

## 五个阶段

| 阶段 | 内容 | 由谁完成 |
|---|---|---|
| 1 | 下载并安装 ego(lite) 浏览器，说明为何统一使用该浏览器 | agent 下载，用户安装 |
| 2 | 启用 `ego-browser` 技能并授予完全访问权限 | 用户授权 |
| 3 | 在受控标签页打开用户指定的网站 | agent 操作 |
| 4 | 按网站实际情况处理登录 | 用户本人 |
| 5 | 开放式询问「你想让我在这个网站中操作什么？」并引导需求具体化 | 对话推进 |

## 安装

把 `SKILL.md` 放到你的 agent 所使用的 skills 目录中，目录名建议与 frontmatter 的 `name` 保持一致：

```
~/.workbuddy/skills/ego-browser-onboarding/SKILL.md
~/.codebuddy/skills/ego-browser-onboarding/SKILL.md
~/.claude/skills/ego-browser-onboarding/SKILL.md
```

具体路径取决于所用客户端。文档阶段 1 / 附录 A 说明了 ego(lite) 安装后技能落在 `~/.agents/skills/`、而部分客户端从别处读取的目录差异及处理方式。修改客户端配置后通常需要完全重启。

适用对象：支持 `SKILL.md`（YAML frontmatter + Markdown 指令）的 AI 客户端，例如 WorkBuddy、Claude Code 等。

## 设计约束

- **凭据隔离**：登录一律由用户本人在浏览器窗口内完成；agent 不索要、不接收、不保存、不复述密码与验证码。
- **最小影响面**：只操作受控标签页；下载只写入事先告知的路径，不覆盖同名文件，不擅自删除或移动用户文件。
- **不编造状态**：权限未授予、下载页解析失败等情况下如实暂停，不绕道、不谎报可用。
- **不写死链接**：不固化带版本号或哈希的 CDN 直链，优先复用官方安装脚本或从下载页现场解析。
- **输出风格**：面向用户的文本为纯说明书式，步骤化、无寒暄、无情绪铺垫、无署名与引流。

完整规则、排障表与跨站示范句式见 [`SKILL.md`](SKILL.md)。

## 说明

仓库内容为文档与提示词工程资产，不含可执行代码、不含账号凭据，也不包含对任何特定网站业务流程的自动化脚本。使用者应遵守目标网站的服务条款与所在机构的规范。
